# 实现与验证结果

2026-11-27，用户批准按规划实现，并固定显示顺序为：待入图 → 已入图 → 未入图 → 未请求入图。

## 实现结果

- 状态说明和筛选采用同一有序标签表；历史缺少证据的单元格为空，不再单列未知或入图失败徽标。
- 普通发布解析/质量失败保存终态 SQLite 事件与审计，保留幂等校验，跳过正式入图队列。恢复处理旧候选时也复核；正式撤回保留原语义。
- 共享 SQL 分类统一列表、详情、事件和筛选；新增明确的只解析决定，区分匿名新请求与历史无证据记录，无历史回填。
- `lineage_reason` 单独解释正式入图，个人 usage 错误继续保留在其原诊断中。
- 按实际业务节点和关系的前后变化计数，节点按 label 类别、关系按类型分组，分别显示新增/更新/删除。多标签节点按身份去重，仅刷新维护时间不计更新。
- 统计与 Neo4j 回执同事务保存，提交恢复保留原统计；同一事件重读不累加，新事件 already_current 为实测零；旧成功结果无统计明确显示未记录。
- 受理函数直接返回持久化状态，避免为响应头额外读取和反序列化完整 SQL/分析事件。
