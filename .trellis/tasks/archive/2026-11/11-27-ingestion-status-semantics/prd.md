# 统一审计入图状态与影响统计口径

## 目标与授权

2026-11-27，用户要求重新厘清审计页的入图状态，合并含义重叠的状态，并在成功状态中查看节点、关系的影响数量。用户已同意创建 Trellis 任务并进入规划；用户随后批准开始实现，并明确状态展示顺序为：待入图 → 已入图 → 未入图 → 未请求入图。

用户截图仅用于说明当前页面，截图中的旧文案不是新需求。

## 已确认事实

- 当前页面展示六种入图状态：已入图、待入图、未入图、入图失败、未请求入图、入图状态未知。
- 当前 `failed` 指正式血缘存储流程失败，不代表 SQL 解析失败。
- 当前 `blocked` 同时包含解析/血缘质量不满足、旧版本拒绝和策略复核拒绝等情况，不能仅改标签完成新的归类。
- 当前 `/api/analyze` 受理后，由 FlowScope 的 Rust 后台任务直连 Neo4j；不存在另一个单独的 HTTP 入图请求。
- 当前解析失败的 `publish` 请求仍可能进入存储事件队列，然后在存储阶段得到 `incomplete_analysis`；与用户要求的“解析失败未请求入图”不一致。
- 当前成功结果只有 `lineageStatus`、`usageStatus` 和 `reason`，没有实际节点、关系变更统计。
- 入图状态影响审计列表、详情、状态说明、服务端筛选与分页计数；个人使用记录有独立状态。

## 用户已明确的需求

| 展示 | 新含义 | 交互 |
| --- | --- | --- |
| 待入图 | 策略允许入图，已受理并等待执行、执行中或等待重试 | 不将等待中的请求称为已入图 |
| 已入图 | 已确认图中的正式血缘处理成功 | 悬浮查看影响节点和关系数量，节点按 label 分组，关系按关系类型分组 |
| 未入图 | 已进入入图流程，但未能成功完成 | 悬浮查看具体错误或拒绝原因 |
| 未请求入图 | SQL 解析失败，或策略不允许更新正式血缘 | 显示具体原因，不能混淆为存储失败 |
| 空白 | 历史记录没有可靠入图证据 | 不再展示“入图状态未知”徽标及说明项 |

- 不再单列“入图失败”，将真正的入图失败纳入“未入图”。
- 所有普通 SQL 解析失败记录都应归为“未请求入图”，不能显示“待入图”或“未入图”。历史缺少证据的记录仍保持空白，不能伪造曾经执行的情况。
- 节点、关系统计必须来自已提交的入图结果，不能把 SQL 分析产物的节点数、关系数冒充实际图变更。
- 2026-11-27 用户确认：按实际新增、更新、删除分别统计；只匹配到但内容未变化的对象不计为更新。
- 无变更的幂等重放需要明确表达，不得暗示本次重复新增了已有对象。
- 统计归属单个入图事件；同一请求对应多条审计行时，不把同一事件的统计误称为单条 SQL 文件的独立变更量。

## 目标元素与当前行为

- `app/src/components/GraphIngestionStatus.tsx`：`GraphIngestionStatus` 状态徽标及 `StatusLegend` 说明列表，徽标用 `data-ingestion-status` 标记；原因面板使用 `ingestion-reason-tooltip` / `ingestion-reason-popover`。
- `app/src/pages/AuditPage.tsx`：审计表入图状态单元格、`GraphIngestionStatusHelp` 列头说明和 `lineage_status` 筛选项。
- 当前未知状态会生成徽标，成功徽标只有静态说明，没有统计；调整后历史未知单元格为空，成功徽标支持统计说明。
- API 当前模型缺少实际变更统计，需先补后端结果，再接 UI。现阶段依据源码核实，尚未运行隔离实例验证新 API。

## 验收条件

1. 状态说明只列出四个有明确业务含义的状态，表格历史未知状态为空。
2. 普通 SQL 解析失败不会排队执行正式血缘更新，展示为未请求入图，保留解析错误和审计证据。
3. 策略未要求、禁止或写入前复核不再允许正式血缘更新时，展示为未请求入图，并可解释原因。
4. 策略允许且有效的入图请求，在排队、执行及可重试阶段展示待入图；刷新到已确认提交后才展示已入图。
5. 真正的入图失败展示为未入图，悬浮、键盘聚焦与点击可查看具体原因，操作不打开审计详情。
6. 成功入图结果按本次已提交的结果展示节点 label 分组、关系类型分组统计；回滚事务不产生成功统计。
7. 同一事件回读保留原统计，不累加；新事件命中 `already_current` 时显示无新增变更。旧成功结果缺少统计时明确说明，不能默认为零。
8. 列表、详情、筛选、分页总数和状态说明采用相同的状态分类，不能只改当前页的文案。
9. 不改变个人使用关系的权限、执行语义及其独立状态。
10. 覆盖解析失败、策略禁止、质量检查拒绝、旧版本拒绝、队列重试、最终失败、成功、历史无证据与幂等重放的必要验证。

## 非目标

- 不部署或写入生产 Neo4j，不重跑生产入图，不回填历史统计。
- 不修改 SQL 解析器算法，不改变正式血缘权限，不重构队列吞吐与重试机制。
- 不把内部事件、版本或锁节点的数量直接当作用户关注的业务血缘统计；是否单独展示内部统计在技术设计中明确。
