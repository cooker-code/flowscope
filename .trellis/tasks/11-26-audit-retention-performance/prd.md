# 修正 WITH 审计类型并增加日志保留和查询优化

## 目标与授权

正确显示和筛选 WITH 查询的读写类型，在写入策略页配置全局审计保留天数，默认 7 天，删除无用历史审计解析并改善查询。

用户已同意创建任务并进入规划。用户已审查规划并明确同意实施，默认保留 7 天；线上数据和服务尚未修改。

## 已核实事实

- 线上 652177 解析成功，result_json.sqlType=select，statements[0].statementType=WITH，audit_log.sql_type=WITH，结果未截断。页面将 WITH 显示为 —。
- 旧版 extract_audit_flags 取首条有效语句的 statement_type；本地基线已有按最终 sql_type / insert_type 分类及可恢复后台校正，本任务复用。
- 线上共 652,188 条；取证时超过 7 天的记录为 625,193 条，近期约 26,995 条。
- 单次 HTTP 基线：普通首页 52.1ms，SELECT 筛选在 15,002.8ms 客户端超时，7 天以前查询 652.7ms，queued 筛选 1,532.7ms。
- 当前 sql_type 索引不覆盖时间排序；列表每次精确 COUNT，状态筛选和元数据装饰还存在逐行事件查询。
- 仓库没有 dev 分支。独立工作区使用 codex/fix-audit-retention-performance，基线为 master 的 754390a0accc8c3438c0b571da09e4b38c763364，保留已有修复。

## 需求

1. WITH 最终 SELECT 显示 select；WITH INSERT 仍区分 INSERT INTO / INSERT OVERWRITE，不根据文本首关键词猜测。
2. 在截图红框位置增加全局“审计日志保留”配置，默认 7 天，正整数；服务端持久化，刷新和重启保持，仅管理员可修改。
3. 按审计 ts 的 UTC 滚动时间清理过期审计行，包括行内 SQL 和解析 JSON。默认策略适用于已有记录，服务监听后后台分批清理；保存后触发，后续周期执行，遇锁退让。
4. 不改正式图、调用方、token、策略历史和 lineage_events 持久事件。待处理事件关联审计暂保留，结束后按保留期清理。
5. 保留期内旧类型校正继续执行，优先清理再校正，不再读取即将删除的旧解析 JSON。
6. 优化类型筛选与时间排序、状态元数据读取；保留精确总数、调用方隔离、筛选和分页语义。
