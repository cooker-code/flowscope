# 入图状态与真实执行阶段错位

## 1. 根因分类

- B，跨层合同：旧状态把解析/质量拒绝、策略撤回和存储拒绝合在 blocked，又将 failed 单独展示为入图失败，页面无法直接表达是否真正进入正式入图。
- E，隐含假设：旧受理逻辑默认 publish 请求都应该先排队，解析失败直到存储阶段才被拒绝。旧成功结果只有状态，缺少实际变更量。

## 2. 修复范围

不能只改徽标文案。受理和恢复复用纯前置判定；列表、详情、事件和筛选复用同一 SQL 状态分类。保留原事件状态以便追溯。个人 usage 诊断与正式入图原因分开，避免个人写入错误被解释为正式血缘失败。

本轮没有反复修复同一生产故障。验证中的 Docker 退出属于本地测试环境中断；重建任务独占测试库后完成页面验证。

## 3. 预防机制

| 优先级 | 机制 | 落地结果 |
| --- | --- | --- |
| P0 | 受理前置检查 | 解析/质量失败保存终态审计与幂等证据，跳过可执行队列 |
| P0 | 统一分类 | GRAPH_STATUS_CASE 同时服务列表、详情、筛选和事件结果 |
| P0 | 事务内计数 | 业务对象锁下取实际前后值，统计与回执一起提交 |
| P0 | 历史证据区分 | 新只解析决定显式记录；旧缺证据仍为空白；缺统计不能补零 |
| P1 | 回归验证 | 覆盖普通解析失败、撤回、个人错误隔离、分页、并发与提交恢复 |

## 4. 同类风险

正式撤回不依赖重新解析 SQL；其事件、审计和筛选也必须保持一致。解析失败规则不能误拦截撤回。时间戳刷新和重复回执不能夸大更新量，多标签节点总数要去重。

## 5. 知识落地

已更新 CLI lineage-policy / audit-api-spec、storage backend contract 和使用指南。FlowScope 是规范使用方，本仓库没有 `src/templates/markdown/spec/` 模板目录，无需生成不存在的模板副本。验证证据见 `implementation-result.md`。
