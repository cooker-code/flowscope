## 缺陷类别和预防

| 实施中发现的边界 | 根因类别 | 固化措施和证据 |
| --- | --- | --- |
| 首次来源版本 -1 被驱动读为 255 | E：驱动隐含假设；D：只编译不足以证明事务正确 | 查询版本为字符串并严格解析；真实空图库首发测试覆盖，写入 storage spec |
| Schema 采集时间导致重复请求身份变化 | B：解析输出与幂等合同不一致 | 身份只排除 updatedAt，不丢语义；纯转换和 HTTP 重发均覆盖 |
| SELECT 别名不能当作目标物理字段 | B：parser → graph 的位置合同 | 读取 insertTarget 元数据；缺映射/物理元数据阻止激活；CTE/UNION/alias 用例验证 |
| parse_only 可被错误提升为 observe | B：策略权限集合未严格限制 | 明确可降低的动作集合；服务端 403 测试覆盖，前端只提供合法选项 |
| 重启时撤销凭据不能掩盖已提交回执 | B：授权与未知提交恢复顺序 | 先只读对账回执，再授权新变更；真实 HTTP 崩溃模拟覆盖 |
| 深色主题截图处于颜色过渡中 | D：视觉采样时点 | 验证脚本等待主题颜色稳定再截图，不以首帧猜测；保留最终深色截图 |

这些问题均通过实际修正、针对性用例和可执行 spec 记录，不用放宽质量门禁或忽略错误换取通过。

## 一致性复核

- core 和 WASM 不依赖 storage；新生产存储代码没有 Python HTTP、FFI 或子进程调用。
- 主体来自 token 摘要查询，用户/来源/SQL 类型不能自报提升；个人未知表保持独立引用，不写正式物理元数据。
- 来源与共享贡献分别有索引和事务锁；Neo4j 的可重试锁冲突不伪装成成功，使用同 event 重放。
- SQLite outbox 与审计插入一体提交；完整事件未复用审计截断字段，files[] 没有重复 channel 写入。
- 管理员保存使用 revision 冲突检查；后台读已提交策略，预览不保存、不调用 Neo4j；personal audit/event 在后端限制归属。
- 凭据只在浏览器会话内，发送目标限制为同源 API，AI 服务请求保留原认证方式；测试证实跨来源不携带 FlowScope token。
- 前端入口、错误、保存反馈及旧页面均核实；新凭据入口只显示在 REST 模式，WASM 解析没有存储入口依赖。
- 图结构转换的支持范围与后续旧规则对齐、来源接入、PG、生产发布明确分开；未把隔离验证称为生产验收。
