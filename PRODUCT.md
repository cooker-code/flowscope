# Product

## Register

product

## Users

FlowScope serves SQL developers and data engineers who inspect table and column lineage in the existing web workspace. In server mode, platform administrators also inspect SQLite audit history and control which scheduler or personal callers may store analysis results. This task follows the user's confirmed direction to reuse the audit page rather than redesign the application.

## Product Purpose

Make SQL dependencies and transformations understandable, while keeping parsing outcomes separate from storage outcomes. Administrators configure trusted scheduler publishing and personal query footprints. A saved policy must reflect the backend's active revision, and a personal analysis must never silently replace formal lineage.

## Brand Personality

Precise, restrained, practical. Reuse the existing FlowScope typography, light/dark theme, tables, form controls, and plain operational language already present in AuditPage and the SQL workspace.

## Anti-references

Avoid an unrelated marketing dashboard, decorative metric cards, new visual branding, or optimistic success messages before a backend save or graph transaction commits. Do not present submitted SQL as observed execution.

## Design Principles

- Keep policy editing close to the caller identity and its effective action.
- Explain the reason when graph updates are blocked or queued.
- Show parsing, formal lineage, and personal usage as independent states.
- Keep authorization in the Rust API; page visibility is a navigation convenience.
- Preserve the existing SQL workspace and audit navigation.

## Accessibility & Inclusion

Use semantic forms, visible labels, keyboard focus, status text alongside colors, and the existing theme tokens. Allow tables to scroll within their region on narrow screens. No additional accessibility standard or visual rebrand has been requested.
